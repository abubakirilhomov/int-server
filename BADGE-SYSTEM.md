# Жёлтые бейджики (sariq bejik) — учёт на ресепшене

Физический бейджик-пропуск интерна (метка «я интерн» + вход в комнату отдыха и на
уроки). Живёт на ресепшене филиала, выдаётся/сдаётся посуточно. Раньше учёта не
было → бейджики уходили без следа (кейс «отдал другу на 5 месяцев»). Теперь есть
полный журнал + посуточная сверка + сводный отчёт.

Модель учёта: не нумеруем бейджики (они одинаковые) — трекаем **заём** (кому выдан),
привязанный к интерну через ресепшен. Ответственность = журнал, а не серийник.

## Что добавлено

**Backend (int-server):**
- `Intern.receptionBadge` `{ hasBadge, since, branch, givenBy }` — живое состояние.
- `Branch.badgeStock` — общий запас бейджиков филиала.
- `BadgeEvent` — журнал операций (given/returned/lost, когда, кем).
- `BadgeReconciliation` — посуточная сверка ящика (ожидалось/насчитано/расхождение).
- `Mentor.role` += `'administrator'` — роль ресепшена (только свой филиал).
- Эндпоинты `/api/badges/*` (см. ниже), middleware `isReception`, чистая логика в
  `utils/badgeLogic.js` (юнит-тесты `tests/badgeLogic.test.js`).

**Frontend (internship-admin):**
- `/badges/reception` — доска ресепшена (выдать/принять/потерян + закрытие дня).
- `/badges/report` — сводный отчёт для админа (расчёт по филиалам, утечки, сверки).
- Роль «Ресепшен (бейджики)» в форме ментора; администратор ресепшена видит только доску.

## API

| Метод | Путь | Кто | Назначение |
|---|---|---|---|
| GET | `/api/badges/board?branch=` | ресепшен/админ | Доска филиала + счётчики |
| PATCH | `/api/badges/interns/:id` `{action:give\|return\|lost}` | ресепшен/админ | Выдать/принять/списать |
| POST | `/api/badges/close` `{countedInDrawer}` | ресепшен/админ | Закрыть день (сверка) |
| GET | `/api/badges/interns/:id/history` | ресепшен/админ | История бейджика интерна |
| GET | `/api/badges/report` | админ | Сводка: филиалы, утечки, сверки |
| PATCH | `/api/badges/stock` `{branch,badgeStock}` | админ | Инвентаризация (запас) |

Администратор ресепшена работает только со СВОИМ филиалом (branch берётся из токена).
Админ может указать `branch` явно (в теле/`?branch=`).

## Развёртывание (по шагам)

1. **Backend:** запушить int-server в `main` → Railway/Render авто-деплой. Миграции
   БД НЕ нужны (новые поля опциональны, дефолты проставятся).
2. **Frontend:** пересобрать и задеплоить `internship-admin` (Vercel, деплой ручной):
   `npm run build` → деплой. Без этого страницы `/badges/*` не появятся.
3. **Инвентаризация:** ресепшен каждого филиала физически считает бейджики. Админ
   заносит число: `/badges/report` → колонка «Запас» → сохранить (или скрипт ниже).
4. **Аккаунты ресепшена:** админ-панель → Менторы → добавить → роль
   **«Ресепшен (бейджики)»** → выбрать филиал → задать пароль. Логин у ресепшена —
   тот же `mentors/login` (имя + фамилия + пароль). После входа он видит только доску.

## Ежедневный поток ресепшена

- Интерн пришёл → «Выдать». Ушёл → «Принять». Бейджик не вернулся → «Потерян»
  (уменьшает запас, с записью в журнал).
- Конец дня → «Закрыть день» → ввести, сколько бейджиков в ящике → система сверяет
  с ожидаемым (`запас − на руках`) и показывает расхождение + кто не сдал.

## Что видит админ (расчёт, который просили)

`/badges/report`: всего бейджиков, на руках, в ящиках, **утечки** (держит бейджик, но
не активен — тот самый кейс), таблица по филиалам с редактируемым запасом, история
сверок с расхождениями. Клик по интерну в утечках → полная история (доказательство).

## Проверка перед проливкой (рекомендуется)

Юнит-логика покрыта (`npm test`, 61 тест). Полный end-to-end лучше прогнать на
staging/локальном Mongo: поднять int-server + admin, создать тест-филиал/интерна/
ресепшен-аккаунт, пройти выдать→принять→потерян→закрыть день→отчёт. НЕ прогонять
тест-данные на проде.

## Инвентаризация запаса скриптом (опционально)

`scripts/set-badge-stock.js` — задаёт `badgeStock` по филиалам из карты в файле.
Dry-run по умолчанию, запись — с `--apply` (конвенция репо).
